# X Multi Poster

複数の自分の X（旧 Twitter）アカウントを 1 つの画面から管理し、**一括投稿**と**ランダム投稿**を行うローカルアプリです。

- 「＋アカウント追加」→ X 公式の画面でログイン・認可 → 追加完了
- チェックを付けたアカウントへ同じ文章を一括投稿
- 登録した投稿候補から、アカウントごとにランダムな間隔・ランダムな文章で自動投稿

SNS 分析などの機能はありません。認証は X 公式の **OAuth 2.0（Authorization Code Flow with PKCE）** のみを使います。
X の ID・メールアドレス・パスワードを本アプリが受け取ったり保存したりすることはありません。

> ⚠ **必ず先に「[X API 側の制限・注意事項](#x-api-側の制限注意事項)」を読んでください。**
> X API は 2026 年現在**従量課金制**で、投稿 1 件ごとに料金がかかります。また、X のルールでは複数アカウントへ同一・類似内容を投稿することが禁止されています。

## 動作環境

- Node.js **22.13 以上**（組み込みの `node:sqlite` を使用しています）
- macOS / Windows / Linux
- X Developer Console のアカウント（アプリ作成とクレジット購入のため）

## インストール

```bash
git clone <このリポジトリ>
cd twi
npm install
```

`npm install` でバックエンド・フロントエンドの依存関係がまとめてインストールされます。

## 初期設定（開発者が最初の1回だけ）

この章の作業は **アプリを用意する人が最初に 1 回だけ** 行います。
アカウントを追加するたびに Developer Console を触る必要はありません。
2 個目以降のアカウントも、アプリの「＋アカウント追加」から X にログインするだけで追加できます。

### X Developer 側で最初の1回だけ必要な設定

1. <https://console.x.com> に X アカウントでログインします（どのアカウントでも構いません。投稿に使うアカウントとは別でも OK）。
2. **Create App** でアプリを作成します（名前・説明・用途を入力）。
3. **クレジットを購入**します（後述の「[料金](#料金従量課金)」参照）。残高が無いと投稿できません。
   必要に応じて **Spending limit（利用上限）** を設定しておくと安心です。

### OAuth 設定

作成したアプリの **App Settings → User authentication settings → Set up** を開き、次のように設定します。

| 項目 | 設定値 |
| --- | --- |
| App permissions | **Read and write**（投稿に必須。Read only だと投稿時に 403 エラー） |
| Type of App | **Native App**（推奨。Client Secret 不要） |
| Callback URI / Redirect URL | `http://127.0.0.1:8787/api/oauth/callback` |
| Website URL | 任意（例: 自分のサイトや GitHub の URL） |

保存すると **OAuth 2.0 Client ID** が表示されます。これを `.env` の `X_CLIENT_ID` に設定します。

- 「Web App / Automated App or Bot」（Confidential client）を選んだ場合は **Client Secret** も表示されます。その場合は `.env` の `X_CLIENT_SECRET` にも設定してください。
- 本アプリが要求するスコープは `tweet.read tweet.write users.read offline.access` です（投稿・自分のプロフィール取得・トークンの自動更新）。

### Callback URL 設定

- X Developer Console に登録する Callback URL と、`.env` の `X_CALLBACK_URL` は**完全に一致**させてください（末尾の `/` の有無も含む）。
- X の公式ドキュメントでは、ローカル開発では `localhost` ではなく **`http://127.0.0.1`** を使うよう案内されています。
- ポートを変更する場合（`PORT=9000` など）は、Callback URL も `http://127.0.0.1:9000/api/oauth/callback` に変更して両方に登録してください。
- `npm run dev`（開発モード）でも `npm start`（本番モード）でも、Callback URL は同じ（バックエンドのポート）です。

### .env 設定

```bash
cp .env.example .env
```

最低限、次を設定します。

```dotenv
X_CLIENT_ID=ここに OAuth 2.0 Client ID
X_CALLBACK_URL=http://127.0.0.1:8787/api/oauth/callback
```

その他の項目は `.env.example` のコメントを参照してください。

| 変数 | 説明 | 既定値 |
| --- | --- | --- |
| `X_CLIENT_ID` | OAuth 2.0 Client ID（必須） | なし |
| `X_CLIENT_SECRET` | Confidential client の場合のみ | 空 |
| `X_CALLBACK_URL` | Callback URL | `http://127.0.0.1:8787/api/oauth/callback` |
| `PORT` | バックエンドのポート | `8787` |
| `APP_URL` | 認可完了画面の「アプリを開く」リンク | `http://127.0.0.1:8787` |
| `DATA_DIR` | データ保存先 | `data` |
| `SECRET_STORE` | トークン保存先 `auto` / `keychain` / `file` | `auto` |
| `TOKEN_ENCRYPTION_KEY` | `file` 方式の暗号鍵（任意） | 自動生成 |
| `X_MOCK` | `true` で X API を呼ばないモックモード | `false` |

`.env` を変更したらアプリを再起動してください。

## 起動方法

### 普段使い（本番モード）

```bash
npm run build   # 初回と、アプリを更新したときだけ
npm start
```

ブラウザで <http://127.0.0.1:8787> を開きます。

```bash
npm run dev
```

ブラウザで <http://127.0.0.1:5173> を開きます（API は 8787 番で動作し、Vite がプロキシします）。

### お試し（モックモード）

X Developer の設定をする前に画面や動作を確認したい場合は、`.env` に `X_MOCK=true` を設定して起動します。
X API を一切呼ばず、「＋アカウント追加」でダミーアカウントが追加されます（X のログイン画面は表示されません）。
本番利用時は必ず `X_MOCK=false` に戻してください。

## アカウント追加方法

1. 画面右上の **「＋アカウント追加」** を押します。
2. 新しいタブで **X 公式の認可画面**（`x.com`）が開きます。
3. X にログインし（ログイン済みならそのまま）、**「アプリにアクセスを許可」** を押します。
4. 「✓ 接続完了」と表示されたらタブを閉じてアプリに戻ります。
   `@ユーザー名`・表示名・アイコンが自動で取得され、アカウント一覧に追加されています。

**2 個目以降のアカウント**も同じ手順です。ただし X の認可画面は**ブラウザで現在ログイン中の X アカウント**に対して表示されるため、

- 先に x.com で追加したいアカウントに**切り替えて**から「＋アカウント追加」を押す、または
- 認可画面で別アカウントに切り替える／ログアウトして別アカウントでログインする

必要があります（X 側の仕様で、アプリから「別アカウントでログイン」を強制することはできません）。

### 再認証

アカウントに **⚠ 再認証必要** と表示された場合は、そのアカウントの **「再認証」** を押し、**同じアカウント**で X にログインして認可してください。
別のアカウントで認可した場合はエラーになり、トークンは保存されません。

### 削除

「削除」を押すと、X 側のトークンを失効させたうえで、アプリからアカウントとトークンを削除します。X のアカウント自体には影響しません。

## 一括投稿方法

1. 左のアカウント一覧で、投稿したいアカウントに **チェック** を付けます（「全選択」「全解除」も使えます）。
2. 「一括投稿」の入力欄に本文を入力します。
3. **「選択したアカウントへ投稿」** を押します。
4. 「**3アカウントへ投稿します**」という確認が表示されるので、内容を確認して「投稿する」を押します。
5. アカウントごとに結果が表示されます。

```
@account_A　✓ 投稿成功
@account_B　✓ 投稿成功
@account_C　✕ 投稿失敗　X APIの制限により投稿できません（解除予定 13:15）
```

- 各アカウントへの投稿は**独立して**処理され、1 つ失敗しても他は継続します。
- 投稿中はボタンが無効になり、連打や通信の再送でも二重投稿されません（リクエスト ID による冪等化）。
- 文字数カウンターは X の数え方（日本語 1 文字 = 2、URL = 23）の目安です。通常アカウントの上限は 280（日本語のみなら 140 文字）です。

## ランダム投稿方法

### 1. 投稿プールに文章を登録する

「ランダム投稿」パネルの **「投稿プール」** を開きます。

- テキストエリアに **1 行 = 1 投稿** で入力して「N件を追加」を押すと、まとめて登録できます（空行は無視）。

  ```
  今日も疲れた
  おはよう
  眠い
  仕事終わった
  今日何してる？
  ```
  → 5 件の投稿候補として登録

- 各候補は **編集・削除・ON/OFF**（チェックボックス）ができます。OFF の候補は使われません。
- ランダム投稿には **ON の候補が 2 件以上**必要です（同じ文章の連続投稿を防ぐため）。

### 2. 対象アカウントと投稿間隔を決める

- **対象アカウント**：チェックを付けたアカウントが対象です（「左の選択をコピー」で一括投稿の選択を流用できます）。
- **投稿間隔**：最短〜最長（分）を指定します。例：最短 30 分 〜 最長 120 分。

### 3. 開始する

**「開始」** → 確認 → 開始します。

- 各アカウントごとに、次回投稿までの時間が **[最短, 最長] の範囲でランダムに**決まります（固定間隔ではありません）。
- 投稿する文章も投稿プールからランダムに選ばれます。**同じアカウントで直前と同じ文章は選ばれません。**
- アカウントごとに**独立して**スケジュールされます。

```
次回投稿
10:32　@account_A　「おはよう」
10:51　@account_C　「眠い」
11:07　@account_B　「帰宅」
```

- 予定時刻になると投稿され、そのアカウントの次回時刻が再びランダムに決まります。

### 4. 操作

| ボタン | 動作 |
| --- | --- |
| 開始 | 対象アカウントの次回時刻を抽選して開始 |
| 一時停止 | 予定（キュー）を残したまま投稿を止める |
| 再開 | 一時停止から再開。予定時刻を過ぎていたものは**まとめて投稿せず**、新しいランダム時刻に振り直す |
| 停止 | **それ以降の自動投稿を即座に停止**し、予定をすべて取り消す |

※ 停止を押した瞬間に X へ送信中だった投稿（最大 1 アカウント 1 件）は取り消せません。それ以降の投稿は行われません。

### アプリを再起動した場合

登録アカウント・投稿プール・ランダム投稿設定・投稿履歴・投稿キューはすべて保存され、再起動後に復元されます。

**意図しない投稿を防ぐため、ランダム投稿が実行中のままアプリを終了した場合でも、再起動後は自動で再開せず「一時停止」状態で復元されます。**
画面の「再開」を押すと続きから再開します（予定時刻を過ぎていたものは新しいランダム時刻に振り直されます）。

### 自動で一時停止する場合

- X API のクレジット残高不足・利用上限に達した場合
- ON の投稿候補が足りなくなった場合

理由は「ランダム投稿」パネルに表示されます。

## X API 側の制限・注意事項

2026 年 10 月時点で X 公式ドキュメントを確認した内容です。X の仕様・料金は変更されることがあるため、最新情報は公式ドキュメントを確認してください。

### 料金（従量課金）

- X API は **2026 年 2 月から従量課金（Pay-per-use）** が標準になり、**新規開発者向けの無料枠はありません**。Developer Console でクレジットを購入して使います。
- 公式の料金表（[Pricing](https://docs.x.com/x-api/getting-started/pricing)）より：
  - 投稿の作成：**$0.015 / 件**
  - **URL を含む投稿：$0.20 / 件**（高額なので注意）
  - ユーザー情報の取得：$0.010 / 件（本アプリではアカウント追加・再認証時に 1 回だけ使用）
- 例：3 アカウント × 1 日 10 投稿 × 30 日 = 900 投稿 ≒ **$13.5 / 月**（URL なしの場合）
- Developer Console で **Spending limit（請求期間ごとの上限）** を設定できます。上限に達すると API が止まり、本アプリには「X APIのクレジット残高不足または利用上限により実行できません」と表示されます。

### レート制限

[公式のレート制限](https://docs.x.com/x-api/fundamentals/rate-limits)（`POST /2/tweets`）：

| 単位 | 上限 |
| --- | --- |
| ユーザー（アカウント）ごと | 100 リクエスト / 15 分 |
| アプリ全体 | 10,000 リクエスト / 24 時間 |

- 上限に達した場合、本アプリは**投稿を強行しません**。「X APIの制限により投稿できません（解除予定 HH:MM）」と表示し、解除時刻までそのアカウントへの投稿は X API を呼ばずに失敗扱いにします。ランダム投稿では解除時刻以降に次回を予約します。
- 制限を回避する仕組み（複数アプリでの分散など）は実装していません。

### X のルール（重要）

X の [Automation rules](https://help.x.com/en/rules-and-policies/x-automation) では次のことが禁止されています。

- **1 つのアカウント、または自分が運用する複数アカウントで、重複または実質的に同じ内容を投稿すること**
- 重複・実質的に同じ用途のために複数アカウントを作成・自動化すること

そのため、**同じ文章を複数アカウントへ一括投稿すること自体が、X のルール違反（アカウント凍結の対象）になる可能性があります。**
本アプリは技術的には一括投稿が可能ですが、利用はご自身の判断と責任で行い、アカウントごとに内容を変えるなど X のルールに沿った使い方をしてください。

### 重複投稿

X は同じアカウントで直近と同じ本文の投稿を拒否します（403）。本アプリでは「同じ内容の投稿としてXに拒否されました（重複投稿）」と表示します。
ランダム投稿では同じアカウントで直前と同じ文章を選ばないようにしていますが、投稿プールが少ないと X 側で重複と判定されることがあります。候補を多めに登録してください。

### OAuth の仕様

- アクセストークンの有効期限は **2 時間**です。本アプリは `offline.access` スコープで取得したリフレッシュトークンを使い、自動で更新します。
- X のリフレッシュトークンは **1 回しか使えません**。本アプリはアカウントごとに処理を直列化して衝突を防いでいます。**同じデータで本アプリを 2 つ同時に起動しないでください**（トークンが無効になり再認証が必要になります）。
- 認可画面はブラウザで現在ログイン中の X アカウントに対して表示されます。アプリ側から「別のアカウントでログイン」を強制する公式パラメータはありません（[アカウント追加方法](#アカウント追加方法) 参照）。
- 1 つのアプリ（Client ID）で何個でもアカウントを接続できます。利用者ごと・アカウントごとの Developer 設定は不要です。

## よくあるエラー

| 表示 | 原因 | 対処 |
| --- | --- | --- |
| X_CLIENT_ID が未設定です | `.env` 未設定 | [初期設定](#初期設定開発者が最初の1回だけ) を行い再起動 |
| X の認証に失敗しました: Value passed for the client id was invalid | Client ID の誤り | Developer Console の OAuth 2.0 Client ID を確認（API Key ではありません） |
| 認可画面に「Something went wrong」と表示される | Callback URL の不一致、または OAuth 2.0 が未設定 | Developer Console と `.env` の Callback URL を完全一致させる |
| X 側で認可がキャンセルされました | 認可画面で「キャンセル」した | もう一度「アカウント追加」 |
| 再認証したアカウント（@B）が対象（@A）と異なります | 別アカウントで認可した | x.com で @A に切り替えてから「再認証」 |
| ⚠ 再認証必要 / 認証の有効期限が切れています | トークン失効（X 側で連携解除、パスワード変更など） | 「再認証」 |
| トークンの更新に失敗しました | リフレッシュトークンが無効（二重起動、長期間未使用など） | 「再認証」 |
| X APIの制限により投稿できません | レート制限 | 表示された解除時刻まで待つ |
| X APIのクレジット残高不足または利用上限により実行できません | クレジット不足・Spending limit 到達 | Developer Console で残高・上限を確認 |
| 同じ内容の投稿としてXに拒否されました（重複投稿） | 同じアカウントで同じ本文を投稿 | 本文を変える |
| Xに拒否されました。アプリの権限（Read and write）… | App permissions が Read only、アカウント制限など | App permissions を Read and write にして**再認証** |
| ネットワークエラー：Xに接続できませんでした | 通信障害 | 接続を確認。投稿は自動で再送しません（二重投稿防止） |
| 前回の一括投稿を処理中です | 一括投稿の実行中に再度実行した | 完了を待つ |

## トラブルシューティング

**Q. 「＋アカウント追加」を押してもタブが開かない**
ブラウザのポップアップブロックが原因です。画面に表示されるリンクをクリックするか、このサイトのポップアップを許可してください。

**Q. 認可後「接続完了」と出たのにアプリに反映されない**
アプリのタブに戻ると自動で反映されます。反映されない場合は再読み込みしてください。認可画面を開いてから 15 分以上経つと無効になるので、もう一度「アカウント追加」からやり直してください。

**Q. App permissions を Read and write に変更したのに 403 になる**
権限変更前に発行されたトークンには反映されません。各アカウントで「再認証」してください。

**Q. ランダム投稿が始まらない／投稿されない**
- 状態が「一時停止中」になっていないか確認し、「再開」を押してください（再起動後は安全のため一時停止で復元されます）。
- ON の投稿候補が 2 件以上あるか確認してください。
- アプリ（`npm start` のプロセス）が起動している間だけ投稿されます。PC のスリープ中は投稿されません。

**Q. 「OS の資格情報ストアを利用できないため、暗号化ファイルに保存します」と表示される**
Linux で Secret Service（GNOME Keyring など）が無い環境です。トークンは AES-256-GCM で暗号化して `data/secrets.enc.json` に保存されます（鍵は `data/secret.key`）。問題はありませんが、`data/` フォルダの取り扱いに注意してください。

**Q. ポート 8787 が使用中で起動できない**
`.env` の `PORT` を変更し、`X_CALLBACK_URL` と Developer Console の Callback URL も同じポートに変更してください。

**Q. データをリセットしたい**
アプリを終了して `data/` フォルダを削除してください（OS の資格情報ストアに保存されたトークンは「x-multi-poster」という名前で残るため、気になる場合は先にアプリ上で各アカウントを削除してください）。

**Q. ログを見たい**
`npm start` を実行したターミナルに、投稿の成功・失敗、スケジューラーの開始・停止などが表示されます。

## データの保存場所とセキュリティ

| データ | 保存先 |
| --- | --- |
| アカウント情報（ID・ユーザー名・表示名・アイコン URL・状態）、投稿プール、ランダム投稿設定、キュー、履歴 | SQLite（`data/app.db`） |
| OAuth アクセストークン・リフレッシュトークン | **OS の資格情報ストア**（macOS キーチェーン / Windows 資格情報マネージャー / Linux Secret Service）。使えない場合は **AES-256-GCM で暗号化したファイル**（`data/secrets.enc.json`） |

- トークンなどの秘密情報は SQLite に**保存しません**。
- X のパスワード・メールアドレスは本アプリでは一切扱いません（ログインは X 公式の画面で行います）。
- バックエンドは `127.0.0.1` でのみ待ち受け、他サイトからの API 呼び出し（Origin / Host が異なるもの）は拒否します。
- `data/` と `.env` は `.gitignore` 済みです。共有・公開しないでください。

### Tauri への移行について

- フロントエンドは `frontend/src/api/client.ts` 経由でのみバックエンドと通信します。Tauri 化する場合は、
  - バックエンドを **sidecar** として同梱して現在の HTTP API をそのまま使う、または
  - `client.ts` の実装を Tauri の `invoke` に差し替え、`backend/src/services` のロジックを移植する
  のどちらでも対応できます。
- トークン保存は `services/security/secretStore.ts` の `SecretStore` インターフェースで抽象化しているため、Tauri の keyring / stronghold プラグインに差し替えられます。
- OAuth の認可画面はシステムブラウザで開き、完了をポーリングで検知する方式なので、デスクトップアプリでもそのまま使えます。
